How I work as a PM

  1. Discovery

    A structured discovery framework with eight session types, so the first workshop already asks the right questions.

  2. Specs

    BRDs, PRDs and user stories written so engineering can build from them and QA can test against them.

  3. Stakeholders

    Business, tech and client describing the same thing. Most projects fail because nobody wrote down what "done" meant.

  4. Delivery

    Working with engineering through build, UAT and launch, with scope decisions made early instead of late.

  5. Measurement

    A researcher's habit: decide what success looks like before building, then check it with real numbers.
